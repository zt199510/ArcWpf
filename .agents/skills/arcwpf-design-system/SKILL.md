# ArcWpf 设计系统

先读 [架构的主题与视觉规范](../../../docs/architecture.md)，核对组件规格和已有资源。引入图标/字体时读 [来源规范](../../../docs/sources.md)。

## 处理流程

1. 确认问题属于全局语义令牌、组件几何还是局部布局。修改全局 Token 前列出受影响控件。
2. 从固定来源提取值，记录 CSS/Arc 名称到 WPF 资源键的映射。原值不可得时注明采用的设计选择。
3. 维护基础、明暗、强调色、应用覆盖的顺序；以实际资源查找和消费应用验证为准。不要仅替换 Gallery 的背景假装完成主题切换。
4. 覆盖普通控件和实际浮层，检查禁用/焦点/错误、长文本和字体回退。涉及已有截图基准的改动先审查差异，再更新基准。

## 关键约束

- 动态主题资源不能被本地硬编码值意外遮盖；Freeze 只用于确实不可变的资源。
- 组件内部数值常量按语义判断，几何计算不必全部变成全局 Token。
- 颜色状态同时提供可理解的文字或图形线索；不要仅靠颜色表达错误。
- 图标与字体保持来源/许可记录，验证中文字体回退和目标 DPI；不能假设 Web 字体在 WPF 下完全相同。

交付：资源变更、映射和影响说明，以及 [验证规范](../../../docs/verification.md) 要求的真实结果和剩余限制。

## 令牌与几何分开

按 [复刻规则](../../../docs/replication-workflow.md) 区分语义令牌、控件尺寸计算和展示容器配置。CSS原值、WPF采用值、转换依据及证据记录在组件参考卡；依赖当前高度的胶囊半径不作为全局9999圆角直接套用。

修复配色/外形前核对主题、字体回退、缩放和初始状态；不通过修改全局资源掩盖单组件模板错误。主示例复用已确认文案及状态，新的视觉方案须明确标为项目设计。
