# ArcWpf 控件开发

读取对应组件规格与 [架构规范](../../../docs/architecture.md)。若缺规格，先补足当前实现必需的基类、状态、公开契约与验收场景，不要求无关的长篇设计。

## 实施决策

- 先选能保留最多原生行为的基类。外观变化可用样式解决；新增稳定交互契约时才引入新控件。
- 先确定 DP 类型、默认值、绑定方向、只读状态和验证/强制转换边界，再实现模板。避免递归属性更新和共享可变默认值。
- 控件不能接管使用者 DataContext。内部绑定显式指向模板父级；程序更新不能意外移除绑定或覆盖动态资源。
- 模板可替换；明确必要部件，对缺失可选部件优雅降级。重新应用模板前解除旧事件。
- 保留命令、自动化与键盘语义。编辑控件以中文合成输入、选区和撤销为实际验证场景。
- C# 行为与 XAML 外观按职责分离；禁止为方便演示让控件引用 Gallery 或业务 ViewModel。

实现 Web 来源控件时，先把参考卡中的布局契约转成 WPF 的 Grid、StackPanel、ScrollViewer 层级。每个固定尺寸都要注明它约束的是根控件还是内部部件；根控件尺寸不能因为内部视觉需要而缩成轨道或图标的尺寸。外壳、标题、数值、前后缀和操作按钮若共同对齐，应放在同一明确的布局关系中，不能靠负 Margin 或偶然的排列顺序补偿。

### 布局与输入闭环

显隐部件或占位修复按[显隐与占位布局回归](../../../docs/replication-workflow.md#显隐与占位布局回归)建立尺寸契约和回归。先区分文本占位提示、按钮预留空间、控件外框与父容器移动；不要仅靠固定槽宽或增加 Gallery 最小高度宣布缺陷解决。

- 模板必须明确自己的尺寸契约：滚动型内容在控件内部提供 `ScrollViewer` 或等价宿主；外层 `StackPanel` 的无限测量不能替代滚动约束。需要填满父容器时使用 `Grid` 的 `*` 行/列，并分别验证内容超出、空内容和窄宽度。
- 公开的 `Height`/`Width` 语义属于整个控件；内部轨道、填充条、图标等固定尺寸只能设置在对应模板部件上。标签、数值和状态内容不得因为部件尺寸被父控件整体裁剪。
- 可点击行或条目至少保留一条明确的真实鼠标命中路径（例如行容器的 PreviewMouse 路由或原生 Button/ListBoxItem 事件），并与键盘路径、禁用状态、选择事件分别验证；不能只依赖测试中手动 Raise 的 Click 事件。
- 模板完成后先做布局烟雾检查：给控件正常宽度、窄宽度、长标题、空说明和超出内容各一次测量，确认实际呈现尺寸、文本省略、滚动范围和命中区域符合布局契约，再补状态和动效。

### 继承控件的模板部件

从已有 ArcWpf 控件派生（如 `ActionButton : Button`）时，先列出父类 `GetTemplateChild` 依赖的部件名及缺失时的行为。父类常在部件缺失时静默返回，构建和属性测试都会通过，但动画实际不运行。

- 要么提供父类需要的全部部件，要么明确不使用该父类行为、改用自身部件实现，并在规格记录。
- 至少一个测试在显示的窗口中触发状态变化，断言动画时钟确实启动（`HasAnimatedProperties` 或中间值），而不只断言最终属性值。
- 父类需要的扩展点用 `private protected` 钩子暴露（如 `IsBusy`），不复制父类逻辑。

## 工作闭环

在真实解决方案存在时执行相应构建与行为测试；新增属性至少在 Gallery 或消费示例中验证绑定和动态更新。对焦点/Popup/IME 等实际窗口场景遵循 [验证规范](../../../docs/verification.md)，构建成功不代表行为通过。

涉及主题、动效时读取架构中的对应章节，只有专门的复杂工作才加载相应项目 Skill。完成后同步规格中的真实 API、差异和未验证事项；不得把规划命令或未经执行的测试写成结果。

## 防止已知适配回归

编码前读 [复刻规则的WPF适配检查](../../../docs/replication-workflow.md)，只检查与当前控件相关的风险。尤其区分CSS胶囊与WPF圆角、原生宿主Padding与模板Padding、字符字形与矢量图标边界。

对定位/外形修复，用最终布局坐标或渲染结果证明修改针对了根因；不只断言Width、Margin、CornerRadius的设定值。保持控件库与Gallery分离，原版主示例与业务验证示例分开。不要将Input的2 DIP补偿推广成通用文本规则。

当模板中的按钮、关闭图标、展开图标或其他内部视觉部件与已有控件相同或相近时，编码前先检查已确认的同类模板，复用其尺寸约束、主题令牌、悬停状态和矢量几何；不要凭名称或记忆重新绘制。外形回归至少检查最终有效尺寸约束，以及图标 `Data.Bounds`、笔画或实际渲染边界等能区分形状差异的结果；只检查 XAML 属性设定值不够。

标题行内的图标、Chevron 和关闭按钮优先放在独立的 Grid/布局单元中，并通过行内对齐实现垂直居中。只有来源规格明确要求重叠，或最终测量证明需要视觉补偿时才使用负 Margin；使用时记录原因，并分别测量文字、命中区域和图标位置。

焦点按[原生行为与视觉装饰分别决定](../../../docs/replication-workflow.md#原生行为与视觉装饰分别决定)处理：先确认来源要求什么外观，再选择WPF机制。保留键盘导航不意味着添加焦点框；`FocusVisualStyle`不是默认必加项，也不能把单个控件的修正推广为统一禁用焦点提示。仅当已确认需要键盘专属焦点装饰时，优先使用 `FocusVisualStyle` 或等效机制，不用 `IsKeyboardFocusWithin` 让鼠标聚焦也显示该装饰。
