# ArcWpf 界面验证

读取组件规格及 [验证规范](../../../docs/verification.md)，选择与改动相关的场景。先检查现有运行入口、测试项目和可用工具，避免虚构 Gallery 命令或自动化能力。

## 执行方式

1. 记录环境与目标版本，复用已有可运行示例。按纯逻辑、STA/Dispatcher 集成、实际窗口、视觉分别记录结果。
2. 针对实际改动运行必要测试。窗口验证覆盖适用的焦点、中文合成输入、Popup 和 DPI；UI 自动化调用必须对应真实可用工具。
3. 截图锁定环境与数据，注明动画模式；对独立 Popup 使用实际窗口捕获。基准差异先审查，不能自动接受全部变化。
4. 缺陷记录触发步骤、预期、实测、环境和证据；区分产品错误、环境差异及未验证假设。

## 结果边界

- 工具不可用时继续可执行的测试，对剩余项给出具体人工步骤，不能推断“应该通过”。
- WPF 渲染需要正确线程和消息循环；不要照搬 Avalonia Headless 方案。
- 自动化点击成功不等于可访问性通过；读屏和 AutomationPeer 契约按实际范围验证。
- 对可聚焦标题、按钮和行项，按[原生行为与视觉装饰分别决定](../../../docs/replication-workflow.md#原生行为与视觉装饰分别决定)分别检查焦点能力与最终外观。鼠标选择、Tab/方向键进入和失焦都应符合已确认的状态契约；不能仅断言“已获得焦点”就判断外观正确，也不能把“存在焦点框”作为通用通过条件。实际窗口检查延期时，明确哪些装饰状态尚未观察。
- 对带图标的标题行验证文字基线、图标实际渲染边界和行内垂直中心；特别检查不同标题长度、描述显隐和 DPI 下图标没有被未解释的定位补偿或换行推离目标位置。来源明确要求重叠时，验证重叠区域和命中区域仍符合规格。
- 对滚动型控件验证父布局给出的有限高度、内容超出后的滚动条和滚轮/拖动响应；不要把 `StackPanel` 的无限测量结果当作滚动通过。对进度、标签或状态组合控件验证固定尺寸只作用于内部部件，整体内容没有被裁剪。
- 对列表、树和导航项实际点击一项，记录命中对象、选择/展开事件和页面或内容变化；只通过 `RaiseEvent` 的程序化结果不能证明真实鼠标命中路径正常。
- 未测量的性能保持定性观察，不能生成看似精确的数据。
- 不为通过检查改写预期行为或覆盖视觉基准。修复后只重复受影响验证，除非新的风险需要扩大范围。

交付简明验证报告：通过、失败、未运行，附证据位置、阻断项与下一步。仅所有约定退出条件满足时才能建议标记“已验收”。

## 定位和证据分层

对可见缺陷使用[同一构建版本的验收](../../../docs/replication-workflow.md#同一构建版本的验收)关联构建、进程和证据。尺寸/占位问题执行[显隐与占位布局回归](../../../docs/replication-workflow.md#显隐与占位布局回归)，同时检查外框、内部内容与父容器；特效反馈按[动效清单](../../../docs/replication-workflow.md#动效逐项核对)逐项验证，不用单张终态截图证明整个动画。

按 [复刻规则](../../../docs/replication-workflow.md) 将反馈先定位到外形、内部布局、状态动效或展示容器。对照参考卡固定文案/初始状态/宽度约束；截图未知DPI时不声称精确像素差异。

分别报告构建逻辑、布局测量、离屏渲染、实际窗口和用户反馈。优先验证能区分缺陷的结果，例如占位与首字符坐标、胶囊平直段，而非仅核对属性值。不要为低风险文本修正增加无意义测试。

用户反馈记录原话、日期、对应修改范围和未知覆盖项。后续修复不自动继承之前的“通过”。用户已延期某项观察时继续可执行检查，不把延期变成虚构通过或新的授权障碍。

## 动画完成后的回归

涉及动画终态、退场或闪烁的变更，按 [动画终态回归](../../../docs/replication-workflow.md#动画终态回归) 检查“过渡中 → 完成并清除时钟 → 后续刷新”。在STA/Dispatcher消息循环中实际推进WPF动画时钟；仅调用内部计算、设置最终状态或关闭动效不足以验证此路径。

检查相关部件的最终有效值及自有时钟清理，再触发与缺陷有关的刷新或反向切换，确认旧状态不会重新出现。优先保留修复前失败、修复后通过的行为回归。真实时钟测试单列为程序化集成证据，不冒充实际窗口视觉观察；用户延期的检查仍标待验收。
