# 验证与交付规范

阶段约定（2026-10-25）：用户明确本阶段不执行状态截图和实际交互观察，先完成四份开发规格。规格可据固定源码/文档进入编码；下列窗口和视觉场景仍是后续验证要求，当前记录“延期/未运行”，不得作为本次规格任务的阻塞条件或声称通过。

## 1. 分层验证

| 层次 | 验证对象 | 运行方式 |
|---|---|---|
| 纯逻辑 | 色彩、弹簧、状态转换、边界计算 | 普通单元测试，尽可能注入时间 |
| WPF 集成 | DP、绑定、模板部件、事件、布局 | Windows + STA + Dispatcher；测试夹具在 M1 选择并验证 |
| 实际窗口 | 焦点、IME、Popup、UI Automation、DPI | 真实 Windows 桌面会话，自动化与必要人工操作结合 |
| 视觉 | 主要状态、主题、布局和截断 | 固定环境截图与基准比较 |

WPF 没有可直接照搬的 Avalonia Headless 测试链路。不得把构建成功或离屏渲染成功当作实际窗口行为通过。工具不能操作某场景时记录“待人工验证”，并提供具体步骤。

## 2. 组件验收矩阵

每个组件按实际适用情况覆盖：

- 状态：默认、悬停、按下、键盘焦点、禁用、错误、加载、空值、长文本。
- 主题：明/暗、强调色切换、应用资源覆盖；覆盖浮层。
- 输入：Tab/Shift+Tab、适用的方向键/Enter/Space/Escape；Input 的中文 IME、粘贴、撤销与选区。
- 数据：初始绑定、双向回写、程序更新、验证错误、重复 ItemsSource 更新。
- 生命周期：重新应用模板、反复打开关闭、卸载重载、宿主销毁；没有残留事件/时钟。
- 环境：100%/150%/200% DPI；涉及 Popup 时加跨显示器移动。高对比度和读屏行为在目标支持矩阵明确声明，不隐含承诺。

未适用项写原因，不把所有控件强制塞入无意义测试。测试应断言用户可见行为或稳定契约，不仅断言实现细节。

## 3. 截图规则

按 [来源规范](sources.md) 分开维护 Arc 还原目标与 ArcWpf 回归基准。首次接受 WPF 基准须对照固定 Arc 目标并记录允许差异；上游更新和修复移植偏差分别记录，不能用实时网站直接覆盖基准。

记录 Windows 版本、运行时、应用提交、视口大小、DPI、字体、主题、强调色、数据和动画模式。首轮人工审查后才接受基准；不得为消除失败而无审查覆盖基准。

静态截图关闭或稳定动画。原站与 WPF 字体抗锯齿存在差异，比较几何、层级、颜色和状态；允许有说明的容差。WPF 自身回归尽量固定同一环境。弹层单独捕获实际窗口；RenderTargetBitmap 不保证包含独立 Popup 窗口。

动效还要记录开始、打断、恢复和结束过程。没有测量不得报告帧率或“无卡顿”。性能预算在 M1 根据基准机器、渲染模式和真实场景设定；检查空闲时不持续更新，列表规模与虚拟化行为有记录。

## 4. 验证记录

记录至少包含：范围、环境、实际执行命令/步骤、预期/实测、截图或日志位置、未测项和已知限制。构建命令应在解决方案创建后从真实路径生成，不提前宣称通过。

每个组件可在其规格末尾记录验收结果；较大报告放 `docs/verification/`，机器生成图片与日志放 `artifacts/`。运行输出与长期基准分开保存。

## 5. 工具与 MCP

以实际可用能力为准：终端用于构建测试，GitHub/HTTP 用于来源检索，Windows UI 工具用于真实窗口。浏览器工具仅验证 Web 参考。MCP 是可选接入方式，不是实现前置依赖；没有原生 Windows 操作能力时不得声称已做 WPF UI 自动化。

## 证据分层与用户反馈

采用 [复刻规则](replication-workflow.md) 的五类结果：构建逻辑、布局测量、离屏渲染、实际窗口、用户反馈。程序化坐标或像素检查必须说明尺寸/环境/容差；测试只验证它实际观察到的内容。模拟卸载或直接调用内部引擎，不能替代可见窗口生命周期测试。

用户原话、日期与对应变更范围写入组件验证记录；未确认的输入/DPI/读屏专项保留未知。后续修改后的版本需新的验证，不无条件继承旧反馈。
