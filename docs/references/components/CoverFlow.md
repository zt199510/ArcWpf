## WPF差异和回归入口

- **绘制方式（WPF适配）**：每张卡的图层先烘焙为平面像素，每帧按逐列反投影在 CPU 上重采样，合成到一张 WriteableBitmap。最初用 Viewport3D，但它的 RenderTargetBitmap 路径依赖 `RGB9Rast.dll`，Wine 中缺失，控件完全无法离屏验证，故改写。代价是 CPU 占用，高 DPI 大舞台下的帧耗时未在真实机器上测量。
- 参数只在 521.6 宽舞台测得，按卡宽比例外推，其他宽度未核对。
- 图片为原创绘制的风景，不使用 Arc 的照片；因此整图差异率不代表还原度，按几何和结构判断。Gallery 中 Arc 未公开统计值的几条路线数据是自拟的。
- 拖动速度逻辑复用 `CardStackMath.Velocity`；未组合 Carousel。
- 回归：`tests/ArcWpf.Tests/CoverFlowTests.cs`。
