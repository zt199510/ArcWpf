## 真实输入（Wine 窗口内注入鼠标和键盘）

| 场景 | 结果 |
|---|---|
| 折叠行 | 点击后 21 行变 25 行，选中该位置，焦点在行上 |
| 布局切换 | 按钮切换单栏和并排；只增、只删的文件自动单栏 |
| 选择与复制 | 点击选中；Shift+方向键得到 5、6、7 三行；Ctrl+C 进入剪贴板的是原文 |
| 跳转 | F7、Shift+F7、头部按钮都能在改动之间移动，只选中目标行 |
| 横向滚动 | Shift+滚轮、左右键、滚动条都能移动文字，行号不动 |
| 多文件 | 标签切换文件，统计数字正确 |
| 滚轮 | 列表到头后滚轮交给外层：内层 0，外层 0→48 |
| 窄窗 | 宽 523 时 Mode 保持 Split，实际为单栏，切换按钮隐藏 |
| 深色 | 运行时切换后，已显示的行颜色更新（另有测试核对令牌值） |

耗时，均在 Wine 下测一次，只作量级参考：10 万行改 2 行的 `FromText` 126 ms；2 万行全部不同的 `FromText` 108 ms（超过编辑上限，整段替换并提示）；显示这 2 万行约 466 ms（含建窗口），视口内只有 19 个行容器。

真实输入发现并修复的缺陷：

- Shift+F7 把选区扩大成一段：按住 Shift 时焦点移动会扩选，而多选状态下给 `SelectedIndex` 赋第一行的值没有效果。改为先清空。**没有单元测试**：必须真的按住 Shift 才会出现，证据是上面的真实输入。
- `⟦U+202E⟧` 和折叠行的 `⋯` 显示成方块：改用 `[U+202E]` 和 `···`。
- 只改换行符时，同时显示“换行符变了”和“No changes”：有提示时改为“The text itself is unchanged.”。
- 文件权限变化拆成两条提示：合并为一条。
- 展开图标的箭头画错了位置：路径里用了相对 `m`，见下。

## 未能验证

## 环境假象

- 点击后按钮出现焦点环：环境中 `SystemParameters.KeyboardCues` 为 True，第十二批已记录。
- 改名时路径间的 `→` 显示成短横：替身字体。真实字体下待确认。
- 深色下普通标识符看起来比着色的词粗：疑为替身字体的渲染差异，**未证实**，需要在真实 Windows 上看。

## 共享图标修复

验证时发现共享图标 `Lucide` 中 8 个画到了 24×24 画布外（66 个里）：`Languages`、`Layers`、`Pencil`、`SearchX`、`ArrowDown`、`Hammer`、`Image`、`CircleCheck`。原因是把多段路径拼成一个字符串时，后面的子路径仍用相对 `m`。这是既有缺陷，用户确认后已修复，每段改为绝对起点。

- 回归 `LucideTests.EveryGlyphStaysOnItsCanvas`：修复前失败（8 个），修复后通过。它只查边界，留在画布内的错位查不出来；已另外搜索全部路径，非开头的相对 `m` 只有这 8 个。
- 用到这些图标的控件专项（ModelPicker、PromptInput、AttachmentTray、ConversationSidebar、CitationList、StreamingMessage、ApprovalCard）加回归测试，共 96 项通过。
- 与 `lucide-static` 1.69.0（ISC，tarball SHA-256 `fc9981e0cac51a0baeaaacf669b6faaa0fbd2427df1b46609a858b6a75df6617`）核对：`Languages`、`Pencil`、`SearchX`、`ArrowDown`、`Image` 的路径一致。`Layers`、`Hammer`、`CircleCheck` 与新版形状略有不同，是图标版本差异，未改。
- 8 个图标单独渲染目视正常（`artifacts/diff-view-2026-11-05/icons.png`）。它们在各控件里的实际显示未逐个复查。
